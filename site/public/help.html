Help

Setting it up, and what to try when it will not connect.

Installing Bridle

In Terminal on the Mac that runs the DeepSeek Harness:

curl -fsSL https://reins.novabox.ai/install | sh

It installs Node if you do not have it, builds Bridle, and links the bridle command into ~/.local/bin. Re-running it is an upgrade, not a reinstall — it is safe to run whenever.

If bridle is not found afterwards, ~/.local/bin is not on your PATH. Add it to your shell profile: 

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
exec zsh

Pairing a phone

bridle pair

A QR code appears with a short code under it. In the app, tap Connect and scan the code — or type the short code if the camera is being awkward. The code is good for 15 minutes and works once.

Pairing is one-time. After it, the app has a key the Mac recognises and reconnects on its own.

Everyday commands

bridle statusIs it running, is it registered with the relay, can it see the Harness
bridle doctorChecks each link in the chain and says which one is broken
bridle devicesPhones this Mac trusts
bridle revoke <prefix>Stop trusting one of them
bridle service installKeep Bridle running in the background after login
bridle backupWrite an encrypted copy of this machine's identity

bridle revoke is the one to remember. Forgetting a Mac in the app only removes it from that iPhone — the Mac keeps trusting the phone until you run this there. That is deliberate: a phone that wants to be forgotten is exactly the phone whose word should not be taken for it.

When it will not connect

Run bridle doctor first. It checks the chain in order and names the broken link.

The app says the Mac is offline

Bridle is not running, or it cannot reach the relay. Run bridle status on the Mac. If it is not running, start it by running bridle with no arguments — or better, bridle service install, so it comes back on its own after a reboot and this stops happening at all.

The app connects but says the Harness is not running

Bridle is fine; the DeepSeek Harness is not. Start the Harness and the app will notice within a few seconds — there is nothing to restart on the phone.

Pairing fails or the code is refused

Codes last 15 minutes and are consumed by the first successful pairing. Run bridle pair again for a fresh one. If it fails immediately, check that the Mac's clock is roughly right — an hour of skew is enough to break a handshake.

It works at home but not away

That is the direct path working and the relay path not. Confirm the Mac has registered: bridle status should show the relay as online.

Searching conversations finds nothing

dsh ships with its session index switched off, so search has nothing to look through until you turn it on. Add this to ~/.dsh/profiles/web/cordis.patch.yml and restart dsh — or just save the file, since the running instance reloads it: 

- id: session-query-sqlite
  config:
    path: ~/.dsh/session-query.sqlite
    openAt: first-search

The app says so too rather than showing an empty list, but this is the fix.

A conversation opens empty

Pull down to reload. If it stays empty, the session's history may be larger than one page; tap Load earlier messages at the top.

Moving to a new Mac

On the old one:

bridle backup ~/reins-identity.bak

On the new one, after installing Bridle:

bridle restore ~/reins-identity.bak

The backup is encrypted with a passphrase you choose and contains this machine's identity and its paired phones. Restoring it means your phones keep working without re-pairing. Losing the passphrase means re-pairing every phone — which is inconvenient rather than fatal.

Removing it

rm -rf ~/.reins
rm ~/.local/bin/bridle

If you installed the background service, run bridle service uninstall first. Nothing else on your Mac is touched, and nothing needs to be removed anywhere else — there is no account.

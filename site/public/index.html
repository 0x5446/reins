Reins

Your coding agent, in your pocket.

The DeepSeek Harness runs on your Mac, where your code and your keys already are. Reins is the iPhone app that drives it — watch it think, approve what it wants to run, answer the question it is blocked on, start the next thing from a train.

Get the app Source on GitHub

Free. MIT-licensed. No accounts. On the Mac that runs dsh, the whole setup is one line:

curl -fsSL https://reins.novabox.ai/install | sh

What it does

Read the run, not a summary of it

Replies stream in as they are written, the model's thinking included. Tool calls arrive as cards — the command, the diff, the output — and the agent's to-do list ticks over as it works through it.

Diffs and terminal output are rendered for a phone screen rather than shrunk to fit one.

Approve with the whole picture

When the agent wants to run something, the request arrives with the full command and diff — not a paraphrase. Approve or refuse from wherever you are. Anything raised while you were away is waiting at the top of the list when you come back, where it cannot be scrolled past.

It finds you when it is stuck

“Your agent is waiting on you”, on the lock screen, the moment the agent stops to ask. The push itself carries nothing else: your phone wakes, opens its own encrypted tunnel to your Mac, and fetches the actual question — so the words never pass through Apple's push service, or our relay, in readable form.

Show it, instead of describing it

Attach a photo from the camera or an image from your library. Sketch a screen on paper, photograph it, and ask for the interface — the sketch goes to the model, the code lands on your Mac.

Pick the model per conversation

DeepSeek, GLM, and the dozens of others your harness knows about. Switch mid-project without touching the Mac — the picker shows what your dsh actually offers, and how hard the model should think.

Every session, one list

Everything the harness is running, grouped by workspace — the same directories you work in on the Mac. Search the full text of every conversation. And when one reaches an interesting branch point, fork it and take both paths.

The security is structural

Three pieces. Reins is the app. Bridle is a small program on your Mac that speaks for the harness. Between them, when they are not on the same network, sits a relay we run on Cloudflare's edge. Bridle dials out, so there is no port to forward and no public IP to need.

The phone and the Mac run a Noise IK handshake with each other — not with the relay — and everything after it travels as sealed frames. The relay switches those frames between two sockets by circuit number. It holds no key material, so it cannot read your prompts, the model's replies, your diffs, or your file paths. That is a property of the design, not a promise about our conduct: an end-to-end test taps the wire and fails if a method name or a machine name ever appears in the clear.

Pairing is a QR code in your terminal, or a short code typed by hand. It anchors keys on both ends — no accounts, no passwords — and both ends show a key fingerprint you can compare when you want to be sure. On the same Wi-Fi, the app talks to the Mac directly and the relay is not involved at all.

All of it is open source — the app, Bridle, the relay, and the protocol — so none of this has to be taken on faith. Read the source, or read exactly what the relay can and cannot see. And if even a content-blind relay is more trust than you want to extend, run your own: bridle --relay wss://your.host is the whole client side.

Setting up

The one prerequisite: a Mac already running the DeepSeek Harness.

  1. Install Bridle on the Mac

    Paste this into Terminal. It takes about a minute.

    curl -fsSL https://reins.novabox.ai/install | sh

  2. Start pairing

    Still in Terminal:

    bridle pair

    A QR code appears, with a short code underneath it.

  3. Point the phone at it

    Open Reins, tap Connect, and scan. If the camera is being difficult, type the short code instead. Pairing is one-time — after this the app reconnects on its own.

# 设计：一机一配对，实例是 Bridle 的配置

状态：v3（2026-08-31）。v2 吸收评审后被"是极简清晰易维护的设计吗"再审了一轮，切掉两块过度工程：机器级锁全家桶（给显式 `REINS_HOME` 用户修监狱）与四阶段双写迁移（给不存在的存量装机修桥）。v1 经跨模型 deep-review 判 NEEDS_FIX——7 条 Warning 全部回证坐实、0 误报（报告 `.review/2026-08-31-one-pair-per-mac-review.md`；consistency 维因引擎路由超时缺席，公司代理恢复后应补跑一轮）。本版逐条吸收，其中两条修的是 v1 自己的真错误（重放缓冲形状、wake 计数维度）。动机来自用户的直接判断："pair 应该是手机和电脑之间的一条链路，一台电脑永远只有一个 pair；bridge 后面映射几个 dsh 实例，是 bridge 自己的配置。"本文把这句话展开成可实施的设计。前作 `docs/instance-awareness.md`（已实施）是当前模型下的显示层补救；本文是模型本身的修正，两者关系见 §7。

## 1. 现状与错位

今天的锚定链：配对 = 信任一对密钥（一个 `REINS_HOME`）→ 密钥指向一个 `dshUrl`。多实例 = 多身份 = 手机上多条配对记录。错位在于：**产品语言说 "pair your Mac"，协议锚定的却是身份**——一台 Mac 可以长出 N 条配对，同名、分不清、relay 上 N 个 socket、N 个推送注册。同名后缀、`bridle instances` 都是这个错位的下游成本。

## 2. 目标模型

```
一台 Mac = 一个 Bridle 身份 = 手机上一条配对
Bridle 配置 N 个 dsh 实例：instances: [{ id, url, label }]
手机在这条链路内选择当前实例；电脑端 CLI 同样能 list/选择
```

- **信任层不变**：锚仍是 X25519 静态密钥 + Ed25519 relay 身份，Noise_IK 不动，relay 依然内容盲。实例选择是**已认证隧道内部**的一个路由参数，不触碰安全模型。
- **实例身份 = Bridle 配置条目**，不是端口。`id` 是稳定 slug（建 entry 时生成），`url` 可改（dsh 换端口只改 url，手机侧无感），`label` 给人看。本地发现（现成的 `probeDsh` 端口扫描 + `host.describe`）只负责帮用户把条目填进来。
- **默认实例**：`instances[0]` 或显式 `default` 字段。现有 `dshUrl` 迁移为唯一条目。

## 3. 隧道协议：连接级选择（不做帧级复用）

握手 hello 载荷新增可选 `instance: <id>`；ready 新增 `instances: [{id,label,reachable}]` 与 `instance: <当前生效 id>`。

- **一条隧道同一时刻只面向一个实例**。切实例 = 断开重握手（与今天切机器同一形状，LAN 亚秒级）。所有既有机制——事件序号、重放缓冲、resync、历史瘦身——保持单后端语义。
- **重放缓冲的形状（review #5，修正 v1）**：**每实例一份共享 `EventLog` + 每手机一个重放游标**。v1 写的 "(peer, instance) 各存一份" 会让内存随 配对数×实例数 相乘——而同一实例的事件流对所有手机是同一份，复制它没有信息量。实例条目删除或换地址时：停泵、释放该实例日志；整体缓冲设实例数上限或字节预算。
- **实例状态的完整所有权（review #2，R5 的闭环）**：属于"每实例一份"的不只是会话缓存——隧道重放游标（`highestSeq`/`everConnected`）、会话列表、workspace、归档集合、审批、提问、默认模型、折叠状态的持久化键，全部带上实例维度；切换时以代际标识取消/丢弃旧实例的迟到回写。验收矩阵必须包含：两个实例撞同一 sessionId、事件序号区间重叠、甲实例审批悬挂时切到乙再切回。
- 不选帧级复用的理由：那要求每一帧带实例标签、每实例独立 seq 空间、app 折叠器全面感知实例维度——深一个数量级，而收益（同屏看两个实例）不是产品前提（"同时只连一台机器"的既有决策同理适用于实例）。
- **会话 id 不跨实例假设唯一**：Bridle 的事件日志、app 的会话缓存一律以 (instance, sessionId) 为键。dsh 的 uuid 实践上不会撞，但正确性不租借运气。

## 4. 推送与后台监听

wake 判定与隧道选择解耦：**Bridle 对每个配置的实例各起一路 mux 监听**，pending 集合与 **attach 计数都带实例维度**（review #4，修正 v1：今天 `flushWake` 用全局 `core.attached>0` 做闸——手机连着实例甲时，乙的审批既不经这条隧道送达、又被全局计数判为"有人在看"，永久漏 wake）。判定式：**某实例有 pending 且该实例的 attach 数为零 → 打 wake**，与其他实例是否有人连着无关。每实例的泵独立启动、独立失败，一个实例挂了不拖累其余。端到端验收：连甲、乙出审批（必须响）；乙不可达而甲正常（甲照常、乙报 harness down）。通知文案可带实例 label（本地生成，不经 relay，隐私模型不变）。

## 5. 两端的呈现

**电脑端 CLI**：
- `bridle dsh list` — 配置的实例 + 各自可达性 + 本地发现的未登记 dsh（"3082 在跑但未登记，`bridle dsh add` 收编"）
- **发现契约（review #3）**：不复用 `probeDsh`（它的契约是"返回第一个应答者"，多实例必漏）。新增 `discoverAll`：遍历全部候选端口收集**所有**通过 `host.describe` 验证的 dsh，再与已配置条目、`bridle instances` 注册表反查出的各 DSH_HOME 运行实例合并去重；自定义端口经配置的扫描范围可发现。
- `bridle dsh add/remove/label` — 管配置；`bridle dsh use <id>` 设默认
- **配置生效规则（review #6）**：**首版明确"改完须重启 Bridle 生效"**——诚实的一行提示，胜过没定义的热更；热更协调器留给后续版本单独设计。删除**当前默认**实例必须先 `use` 指定替代者，否则拒绝（与 reset 的"运行中拒绝"同款脾气）。
- 现有 `bridle instances`（多身份视图）保留为迁移期/排障工具

**手机端**：
- **实现形态一句话（清晰性的关键）**：`MachineSession` 绑定的对象从"机器"加宽为"（机器, 实例）"——切实例复用切机器的**全套既有生命周期**（teardown/rebuild、缓存作用域、"同时只连一个"语义）。评审 #2 列举的那一整串状态所有权（游标/审批/提问/折叠键…）由这一个改动自然覆盖：不是新造一个半相似的子系统，是把现有概念的键加宽。
- 机器条目下出现**实例选择器**（仅 `instances.count > 1` 时渲染——单实例用户界面零变化，同名后缀同款哲学）
- 会话列表、workspace、搜索都在"当前实例"作用域内；切换器显示 label + 可达性
- 急救卡自然升级：ready 带实例清单后，"dsh 层死"一档能直接说*哪个实例*死了、给对应端口的启动命令

## 6. 兼容与迁移

| 组合 | 行为 |
|---|---|
| 老 app × 新 bridle | hello 无 `instance` → 默认实例；ready 多出的字段被忽略（§14 纪律） |
| 新 app × 老 bridle | ready 无 `instances` → 选择器不渲染，行为与今日全同 |
| 现有多身份部署（真+demo） | 继续工作到迁移完成；分阶段迁移见下 |

**机器级唯一：铺路，不修监狱（v3 简化）**：不设 `REINS_HOME` 就只有默认身份——这已经使"一机一配对"对每个没有显式绕开它的人成立。显式设置 `REINS_HOME` 造第二身份是知情行为（开发/演示），由既有机制兜底：home 级单实例锁防身份战争，同名后缀防显示混淆。v2 的机器级锁、`bridle adopt`、`--secondary`、退出期限整套执法机器为此被砍：**它们防御的场景要求用户先显式请求该场景**。评审 R1 的实质（普通用户手机上恰好一条记录）由铺好的默认路径兑现，不需要围墙。

**兼容 = 归一化，不是迁移（v3 简化）**：产品未发布，存量装机为零。配置加载器**永远**把旧 `dshUrl` 读作 `instances: [{id:"default", url:<dshUrl>}]` 的别名——一行归一化，无双写窗口、无版本期、无观察期。`bridle reset` 依旧不可逆，所以现存真+demo 双身份的收编顺序仍是"先加实例条目、手机验证、再 forget、最后 reset"——但那是一条**个人 runbook**（四条命令），不是产品要背的迁移机制。

## 7. 与 instance-awareness（已实施）的关系

| 已实施件 | 命运 |
|---|---|
| 急救卡 / 分层诊断 / 机器详情页 / rename 保护 | **原样有用**，与配对模型无关 |
| ready.harness {url,home} | 被 §3 的 `instances`+`instance` 取代为超集；字段保留一个版本期（老 app 还在读） |
| 同名后缀 | 退化为迁移期保护：多身份仍合法存在期间继续兜底；派生实现，无人触发时零成本 |
| `bridle instances` / `reset` | 保留：多身份排障与迁移工具 |

## 8. 明确不做

| 不做 | 理由 |
|---|---|
| 帧级实例复用 | 见 §3；深一个数量级，收益不是产品前提 |
| 跨实例聚合视图（一屏看所有实例的会话） | 同上；且与"同时只连一台"的既有决策同构 |
| 自动收编发现的 dsh | 发现只提示，登记要人点头——一个陌生端口上的 dsh 不该自动获得被手机遥控的资格 |
| 删除多身份机制 | 迁移期照顾存量；且"两台真机器"仍然是多配对的正当场景 |
